Hybrid Flow Shop CP-LNS 최적화 Workflow

requirement_docs/20260517_flow.md · 2026-05-17

이 문서는 configs_mip_lb/20260515/main_metadata_20260516_candidateD_leaninit_taufirst_oraclepush_50pilot_2nc.yaml에 정의된 13단계 최적화 파이프라인의 전체 구조, 각 단계의 역할, 데이터 흐름, 시간 배분 전략을 설명한다.

At a glance

  • 13단계 파이프라인: 셋업(1–3) → 초기해 생성(4–6) → 2단계 Retained Stage CP+Dispatch(7–10) → 시간 예산 설정(11) → Suffix Probe(12) → 최종 CP-SAT(13).
  • 가장 핵심·복잡한 단계는 두 곳: [5] Tau Coarsened CP(대량 후보해 생성, 가장 많은 시간 소비)와 [12] Suffix Probe Portfolio(5개 lane 경쟁적 프로브).
  • 대부분의 시간 제한은 multiplier × J × S 형태로 문제 규모에 비례한다.
  • Workload(large / high-stage / default)에 따라 CP 모델링 범위와 시간 배율을 적응형으로 차등 적용한다.
  • 최종 단계는 consume_all_remaining=true로 잔여 시간을 전량 소비하며 LNS-only로 전역 최적화한다.

단계별 상세 설명

1set_step_checkpointing

역할: Step checkpointing 활성화. 각 subroutine 종료 시 현재 상태(해, 타이머, 컨텍스트)를 자동 저장하여, 비정상 종료 시 해당 checkpoint부터 재개(resume)할 수 있도록 한다.

파라미터값설명
enabledtrueCheckpoint 저장 활성화

2set_random_seed

역할: 난수 시드 42 고정. CP-SAT 솔버, dispatch 휴리스틱의 난수성(랜덤 타이브레이크, LNS 다양화 등)을 결정론적으로 만들어 재현 가능한 실행을 보장한다.

파라미터값
seed42

3apply_shdlb

역할: SHDL Bound(Static Holding Dispatch Lower Bound) 적용. 각 스테이지의 기계 수와 가공 시간을 기반으로 makespan의 하한(lower bound)을 계산하여 solution_manager에 등록한다. 이후 CP 모델의 primal bound 판단, LNS acceptance 기준 등에 활용된다.

4initialize_by_dispatch_portfolio

역할: 다양한 dispatch 휴리스틱을 포트폴리오로 실행하여 초기 실행 가능해(initial feasible solution)를 생성한다.

동작 방식

  • compact 포트폴리오에 정의된 dispatch 방법들을 실행
  • 각 결과 후보 중 best 전략으로 최선 makespan 선택
  • include_stage_agg=true면 stage-aggregated dispatch variant도 포함

핵심 파라미터

파라미터값설명
portfoliocompact사용할 dispatch 포트폴리오
include_stage_aggtrueStage-aggregated dispatch 포함
cap_portions[0.25]용량 제한 비율
selection_strategybest최선 makespan 선택
error_if_infeasiblefalse실행 불가능해 허용 (Skip)

5initialize_by_tau_coarsened_cp 핵심 단계

역할: Tau Coarsening 기법으로 문제를 축소한 후, 다양한 경로(Dispatch → NEH → PW-CP → CP-SAT)를 통해 대량의 후보해를 생성하고 원래 문제로 복원(restore)하여 최선의 초기해를 선택한다. 이 workflow에서 가장 복잡하고 핵심적인 초기해 생성 단계이다.

세부 파이프라인 (단일 τ=5 기준)

τ=5 sub-pipeline (Dispatch → NEH-CP → PW-CP Chain → Surrogate CP → Restore) 
τ=5 인스턴스 생성 (가공 시간 축소)
  │
  ├── 1. Dispatch (축소 문제)
  │     ├── bn2d_all_stages × cap_portions[0.2,0.25,0.3]
  │     ├── best_of_mixed_dispatches × cap_portions[0.2,0.25,0.3]
  │     └── machine_then_job variants (mtj/jtm 모두)
  │     → 최대 12개 후보 (top_k=20, 중복 제거)
  │
  ├── 2. NEH-CP (축소 문제, best dispatch 기준)
  │     ├── batch_size=15, sequential 실행
  │     └── CP 시간: 0.0015 × J × S sec/batch
  │
  ├── 3. PW-CP Chain (축소 문제, NEH 결과 기준)
  │     ├── batch_size_ratio=0.05
  │     ├── unfixed_batch_count=2→3→4→5→6 (step=1)
  │     └── CP 시간: 0.0015 × J × S sec/batch
  │
  ├── 4. Surrogate CP Solve (축소 문제)
  │     ├── Reference: PW-CP chain 최선 결과
  │     ├── TL: 0.12 × J × S sec
  │     └── Snapshots: 최대 20개
  │
  └── 5. Restore (원래 문제)
        ├── 각 후보 × stage_sequence 복원
        └── 각 후보 × machine_sequence 복원
        → ~78개 후보 중 최선 makespan 선택

폴리시(Polish)는 비활성 (polish_tl_nc_multiplier=null).

특이사항

  • Surrogate NEH-CP만 LNS-only로 실행 (surrogate_neh_use_lns_only=true). Surrogate CP solve와 PW-CP는 LNS-only가 아님 (surrogate_use_lns_only=false, surrogate_pw_cp_use_lns_only=false)
  • 모든 후보해에 make_semi_active() 적용
  • CP-SAT에 diversify_lns_params, solution_pool_size=8 설정
  • cp_model_probing_level=1 — CP-SAT 기본값은 2이므로, 이 설정은 probing 강도를 한 단계 낮춘 비-기본값이다 (0=완전 비활성, 2=기본)

6critical_schedule_repair_ls

역할: Critical Schedule Repair Local Search. 현재 최선해의 critical path를 분석하여 작업 이동, 기계 변경, 인접 교환 등을 통해 makespan을 개선하는 국소 탐색이다.

동작 방식

LS round 구조 (Stage Insertion → Machine Insertion → Adjacent Swap) 
for round = 1 to max_rounds(=2):
  │
  ├── Stage Insertion (2 passes, max shift=4)
  │   └─ 스테이지 내 작업 순서상 위치를 재배치 (최대 ±4칸 이동)
  │
  ├── Machine Insertion (2 passes, max 3 candidates/op)
  │   └─ 작업(operation)을 같은 스테이지의 다른 기계로 재할당
  │
  └── Adjacent Swap (2 passes, max 100 pairs)
      └─ 인접 작업 쌍 교환
파라미터값설명
max_rounds2전체 LS 라운드 수
tl_nc_multiplier0.006LS 시간 제한 = multiplier × J × S
target_stage_modeall모든 스테이지 대상
stage_insertion_passes2Stage insertion 반복 횟수
machine_insertion_passes2Machine insertion 반복 횟수
adjacent_swap_passes2Adjacent swap 반복 횟수

7apply_retained_stage_cp_lb

역할: Retained Stage CP Lower Bound. 전체 스테이지 중 일부(retained stage)만 CP-SAT로 정확히 모델링하고 나머지 스테이지는 head/tail·compressed lag로 완화(relaxation)하여, makespan의 유효한 하한(lower bound)을 계산한다. first_n_quantiles_last 모드는 스테이지 인덱스 순서를 분위로 잘라 retained stage를 선택한다(작업 부하 기준이 아님).

동작 방식

Retained Stage CP LB 절차 
1. retained stage 선택 (first_n_quantiles_last, quantile_count=4)
   → 첫 스테이지 + 인덱스 25/50/75% 절단점 스테이지 + 마지막 스테이지
2. retained stage만 CP-SAT로 정확히 모델링
   (interval 변수, 스테이지별 cumulative 용량, 인접 retained stage 간 precedence)
   비-retained 스테이지는 head/tail·compressed lag로 완화
   변수 도메인 상한은 incumbent makespan(input_ub) 사용
3. makespan 최소화 → 유효한 하한(lower bound) 산출
4. 탐색 중 발견한 retained-stage 부분해를 snapshot으로 저장 (최대 96개)
파라미터값설명
retained_stage_modefirst_n_quantiles_last인덱스 분위 절단점 스테이지를 retained로 선택
quantile_count4분위 수 (절단 비율 25/50/75%)
threads16CP-SAT 스레드
tl_nc_multiplier0.08CP 시간 = 0.08 × J × S
snapshot_solution_limit96중간 해 스냅샷 제한

8dispatch_from_retained_cp

역할: Retained Stage CP에서 생성된 스냅샷 포트폴리오를 dispatch 휴리스틱과 결합하여 완전한 실행 가능해를 재구성한다. CP의 부분해를 dispatch로 완성(mixed scheduling)하고, 다양한 순위 기반 변형(consensus, bottleneck, extended rank, dynamic priority)을 시도한다.

동작 방식

dispatch_from_retained_cp 절차 
1. Retained CP 스냅샷에서 상위 4개(top_k=4) 선택
2. 각 스냅샷에 대해:
   ├── Mixed schedule (이전 스테이지 + 이후 스테이지)
   ├── Consensus rank dispatch
   ├── Tail bottleneck rank dispatch
   ├── Extended rank variants
   └── Dynamic priority dispatch
3. cp_local_repair (max_passes=3, top_k=2)로 정련
4. 최선 makespan 선택 (slack=0, best_makespan 전략)
파라미터값설명
respect_anchor_stage_release_lbtrue고정 스테이지의 release LB 존중
cp_local_repair_max_passes3CP repair 반복 횟수
include_consensus_ranktrueConsensus rank dispatch 포함
include_tail_bottleneck_ranktrueTail bottleneck rank 포함
use_retained_cp_snapshot_portfoliotrueretained CP 스냅샷 사용
retained_cp_snapshot_top_k4상위 4개 스냅샷 선택

9apply_workload_adaptive_retained_stage_cp_lb

역할: 7번 단계의 workload 적응형 버전. 문제 규모(workload)에 따라 CP로 정확히 모델링할 bottleneck 스테이지 수를 동적으로 결정한다.

차별점

  • first_topk_bottlenecks_last 모드: retained stage = [첫 스테이지 + 평균 부하 상위 bottleneck k개 + 마지막 스테이지]
  • large_workload_threshold=1800: workload ≥ 1800인 large 인스턴스는 4개, small은 3개의 추가 bottleneck 스테이지 포함
  • bottleneck_band_radius=1은 config에 지정되어 있으나 first_topk_bottlenecks_last 모드에서는 사용되지 않음 (band 확장은 first_bottleneck_band_last 등 band 계열 모드 전용)
파라미터값설명
retained_stage_modefirst_topk_bottlenecks_lastBottleneck 중심 CP 대상 선정
small_extra_bottleneck_count3Small 인스턴스 추가 bottleneck 수
large_extra_bottleneck_count4Large 인스턴스 추가 bottleneck 수
large_workload_threshold1800Large 판단 기준 workload

11set_stage_workload_adaptive_final_time_reserve

역할: 최종 CP 최적화 단계(13번)를 위한 시간 예산(time reserve)을 workload와 stage 수에 따라 적응형으로 설정한다.

12suffix_probe_portfolio 가장 정교한 구성요소

역할: 이 workflow에서 가장 정교한 구성 요소. 여러 NEH/PW-CP 조합(lane)을 경쟁적으로 프로브(probe)하여 가장 유망한 lane을 선택하고, 해당 lane의 suffix(후속 단계)를 실행한다. 5개의 lane + fallback으로 구성된 포트폴리오이다.

핵심 메커니즘

Probe → Lane 선정 → Suffix 실행 메커니즘 
0. (사전 가드) incumbent와 LB 사이의 gap 비율 확인
   gap_ratio = (incumbent_obj − LB) / |LB|
   - gap_ratio < min_incumbent_bound_gap_ratio(0.003 = 0.3%)이면
     5개 lane portfolio 전체를 건너뛰고 fallback_steps만 실행
     (incumbent가 이미 LB에 충분히 근접 → lane probe 생략)
   - run_if_bound_missing: true → LB를 구할 수 없으면 portfolio를 그대로 실행
1. 각 lane의 probe_steps를 순차 실행 (lane-local 스케줄 복사본에서 평가)
2. probe 완료 후 makespan 평가
3. 최선 probe makespan의 lane 선정
   - accept_equal_obj_from_later_lane: false (동점 시 먼저 평가된 lane 우선)
   - commit_equal_obj: true (선정된 해를 동점이어도 SolutionManager에 commit)
4. 선정된 lane의 suffix_steps 실행

주요 설계 결정 (Design Rationale)

1. Tau Coarsened CP의 대량 후보해 생성
다양한 경로(Dispatch → NEH → PW-CP → CP)와 다양한 복원 방식(stage_sequence, machine_sequence)을 통해 구조적으로 다양한 후보해를 대량 생산한다. 이것이 단일 CP-SAT 실행보다 더 좋은 초기해로 이어진다.
2. 2단계 Retained Stage CP + Dispatch
Retained Stage CP를 두 번(일반형 + workload 적응형) 수행하는 이유: 1차는 quantile 기반으로 전체 구조 파악, 2차는 bottleneck 집중 탐색으로 부족한 부분 보완. 각 결과를 dispatch로 완성하여 실행 가능해를 보장한다.
3. Suffix Probe Portfolio의 경쟁적 Lane 선택
여러 NEH 전략을 경쟁시켜 instance 특성에 가장 적합한 전략을 동적으로 선택한다. CP 시드 유무·profile fix 시점·retained CP sequence 활용·PW-CP interleaving 등 각기 다른 귀납적 편향(inductive bias)을 가진 lane을 준비하고, 짧은 probe로 평가 후 최선 lane의 suffix만 본격 실행한다. incumbent가 이미 LB에 근접해(gap < 0.3%) lane probe가 무의미하면 가벼운 fallback steps로 대체한다.
4. 최종 CP-SAT 전량 소비
모든 이전 단계를 통해 확보한 좋은 reference 해를 바탕으로, LNS만으로 잔여 시간을 전량 소비하여 추가 개선을 도모한다. consume_all_remaining=true로 설정되어 stopping criteria의 timelimit까지 점유한다.
5. Workload 적응형 시간 배분
large / high-stage / default 인스턴스를 구분하여 시간 배율을 차등 적용. small 인스턴스에는 덜, large/high-stage에는 더 많은 시간을 할당하여 문제 규모에 따른 공정한 최적화 기회를 제공한다.
