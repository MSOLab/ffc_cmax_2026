Tau-Coarsened CP 초기해 생성

requirement_docs/algorithm/initialize_by_tau_coarsened_cp.md · def initialize_by_tau_coarsened_cp (hfs_cp_lns.py)

At a glance

  • 문제 축소 → 대리 최적화 → 복원 → 정련의 4단계 파이프라인
  • 가공 시간을 τ배 축소하여 빠르게 풀고, 대량의 후보해를 생성하여 최선의 해를 선택
  • Dispatch, NEH, SW-CP, CP-SAT 등 다양한 경로를 통해 탐색 다양성 확보

개요

Tau-Coarsened CP는 Hybrid Flowshop의 초기 실행 가능해(initial feasible solution)를 생성하는 알고리즘입니다. 원래 문제를 τ배 축소(가공 시간을 τ로 나누고 올림)하여 작고 빠른 surrogate 문제로 변환한 뒤, 다양한 방법으로 후보해를 대량 생산하고, 이를 원래 문제로 복원해 최선의 초기해를 선택합니다.

Algorithm Pipeline

Tau Coarsening→ Surrogate Optimization→ Restore→ Polish

목적 및 제약

Objective
모든 후보해(restored + polished) 중 makespan이 가장 작은 해를 초기해로 선택

Invariants (절차가 보장하는 불변식)

  • 스케줄 실행 가능성: 복원된 모든 후보해는 원래 가공 시간에서 유효한 Hybrid Flowshop 스케줄이어야 함.
  • 작업 순서 보존: tau 해의 순서 정보(stage/machine sequence)가 복원 시 보존되어야 함.
  • 구조 보존: 작업 수, 기계 수, 스테이지 수는 동일하며 가공 시간만 축소됨.

핵심 아이디어

  1. 문제 축소 (Tau Coarsening): 가공 시간을 max(1, ceil(p[j,i] / τ))로 변환하여 모델 규모를 줄이고 CP 풀이 속도를 비약적으로 향상시킵니다.
  2. 다양한 경로로 후보해 생성: Dispatch, NEH-CP, SW-CP, CP-SAT 등 여러 경로를 통해 다양한 해 공간을 탐색합니다. 단계 실행 순서는 surrogate_neh_position에 따라 달라집니다.
  3. 복원 (Restore): 축소 문제에서 얻은 순서/할당 정보를 원본 가공 시간에 적용하여 실행 가능해로 변환합니다.
  4. 최선 선택: 복원 및 정련 과정을 거친 모든 해 중 최적의 Makespan을 가진 해를 최종 선택합니다.

파이프라인 단계별 상세

NEH 실행 위치에 따른 순서 차이

surrogate_neh_position의 기본값은 after_cp입니다. before_cp이면 dispatch → NEH → SW-CP → CP 순, after_cp이면 dispatch → CP → NEH 순으로 실행되며 이때 SW-CP chain은 실행되지 않습니다. 아래 1~5절은 before_cp 기준 순서로 기술합니다.

1. Tau Coarsening (문제 축소)

scaled_instance = _make_tau_coarsened_instance(tau)
# p[j,i] = max(1, ceil(original_p[j,i] / τ))

τ값이 클수록 CP가 빠르게 풀리지만 원래 문제와의 괴리가 커집니다. 통상 1~10 사이 값을 사용합니다.

2. Dispatch 초기해 생성

변수설정값 / 의미
cap_portion설정된 값 목록 (예: 0.2, 0.25, 0.3)
method_listbn2d_all_stages, best_of_mixed_dispatches 등
variantsTrue면 mtj와 jtm 모두 시도하여 다양성 확보
top_k상위 K개 선택 (중복 시그니처 제거)

3. NEH-CP 개선

surrogate_neh_enabled=True일 때 동작하며, NEH 삽입 단계마다 소규모 CP 서브문제를 풀어 작업 순서를 결정합니다. surrogate_neh_position에 따라 실행 위치와 동작이 다릅니다.

before_cp — CP에 전달

dispatch 최적해를 NEH로 개선한 뒤 surrogate CP의 reference로 넘깁니다. 이 경로에서만 SW-CP chain이 동작합니다. 목록 surrogate_neh_added_batch_sizes를 순회하며, sequential=True면 결과가 체인으로 연결됩니다.

after_cp — CP 후보 개선 (기본값)

CP 풀이 후 surrogate_neh_sources에 속하는 후보마다 NEH를 적용해 {source}_neh 후보를 추가합니다. 스칼라 surrogate_neh_added_batch_size만 사용하며 목록·sequential·SW-CP는 적용되지 않습니다.

Example (before_cp)
sequential=True, added_batch_sizes=[15] → dispatch → NEH(batch=15) → dispatch_neh_b15

4. SW-CP Chain (Sliding-Window CP)

NEH 결과를 시작해로 하여 윈도우 크기(unfixed_batch_count)를 점진적으로 증가시키며 체인으로 실행합니다.

SW-CP Execution Chain

NEH Result→ PW(unfixed=2)→ PW(unfixed=3)→ ...→ PW(unfixed=6)

5. Surrogate CP Solve

CP-SAT 모델 구성 
- 목적함수: minimize makespan
- 참조 스케줄: surrogate_dispatch_before_cp=True 시 시작점 제공
    · before_cp NEH 경로: SW-CP / NEH 최선해
    · 그 외(after_cp / NEH 비활성): best dispatch
- 제약: add_reference_precedence=False 시 순서 hard 제약 없음
- 저장: surrogate_cp_snapshot_solution_limit만큼 중간 해 저장

6. Restore (원래 문제로 복원)

stage_sequence

스테이지별 (시작 시간, 종료 시간, job index) 순으로 정렬 → 원본 가공 시간으로 greedy 기계 배정

machine_sequence

기계별 작업 순서를 그대로 유지 → 동일 기계에 원본 가공 시간으로 배정

make_semi_active=True(기본값)이면 복원 후 정규화로 불필요한 idle time을 제거하며, 이후 validate_schedule()로 실행 가능성을 검증합니다.

7. Polish (원래 문제 CP 재탐색)

복원된 해를 reference로 원래 문제에서 CP 재최적화를 수행합니다. polish_tl_nc_multiplier와 polish_computational_time이 둘 다 null이면 polish 단계가 생략됩니다.

주의사항 및 응용 고려사항

Diversity

info
단일 경로보다 Dispatch → NEH → SW-CP → CP로 이어지는 다양한 구조의 후보해를 확보하는 것이 더 좋은 초기해 탐색의 핵심입니다.

Coarsening Error

warn
τ가 클수록 계산 속도는 빨라지지만, Restore 시 원래 문제와의 괴리가 커져 restoration 품질이 떨어질 수 있습니다.

Restore Mode

ok
stage_sequence는 유연한 기계 배정을, machine_sequence는 τ-해의 기계별 작업 순서를 엄격히 보존합니다.
